## الملفات
- `data/pos_*.csv` — البيانات بشكل جداول `pos_*` الحية تماماً (UTF-8).
- `import_to_supabase.sql` — سكربت التحميل (psql). معاملة واحدة: إما ينجح كله أو لا يكتب شيئاً. آمن لإعادة التشغيل (المعرّفات ثابتة مشتقة من معرّفات النظام القديم).
- `sql/01_build_migration_views.sql` — يُشغَّل على قاعدة مؤقتة فيها النسخة المستعادة؛ ينتج جداول `mig.t_pos_*` التي صُدّرت إلى `data/`.

## خطوات التشغيل
1. **مشروع تجريبي أولاً**: مشروع Supabase فارغ → شغّل السلسلة `supabase/migrations/0001..0056` → أدخل العملاء الحاليين (`sql/pos-customers-import.sql`) → ثم من داخل هذا المجلد:
   ```
   psql "<CONNECTION_STRING>" -v DRY_RUN=1 -f import_to_supabase.sql
   ```
   يطبع الأعداد واستعلامات التحقق ثم يتراجع (rollback) بلا كتابة.
2. راجع الأعداد، «must all be 0»، ومجاميع السنوات/الفروع مقابل النظام القديم.
3. الإنتاج — خارج ساعات العمل، وبعد نسخة احتياطية من Supabase:
   ```
   psql "<CONNECTION_STRING>" -v DRY_RUN=0 -f import_to_supabase.sql
   ```
4. افتح التطبيق فوراً بعد الاستيراد وتحقق من زمن التحميل.

استخدم connection string الخاص بـ postgres المباشر (Settings → Database) — يتجاوز RLS. لا تضع كلمة المرور في أي ملف.

## قواعد التحميل (بحسب مراجعة مطوّر المنظومة + المخطط الحي)
- المواقع: بحث بالاسم (فرع 11 يونيو / فرع السراج / مخزن جنزور). الفرع في الفواتير القديمة مشتق من الخزينة (الرئيسية + مواد البناء → السراج، خزينة 11 يونيو → 11 يونيو).
- الموردون: يُدمج بالاسم إن وُجد. المنتجات: `ON CONFLICT DO NOTHING` — القيم الحالية لا تُمسّ، يُملأ `supplier_id` الفارغ فقط.
- العملاء: مطابقة بالرقم (إذا اتفق الهاتف) ثم بالهاتف المطبَّع (بدون الصفر الأول). الأرقام المكررة لأشخاص مختلفين (الفرعان كانا يعطيان نفس الأرقام) تأخذ لاحقة `-<old_id>`. ~178 عميلاً جديداً فقط.
- المبيعات 10,230 (منها 458 مرتجعات بكميات سالبة) بأرقامها الأصلية؛ `created_by`/`idempotency_key` = null.
- الرصيد المستحق حُسب من الدفعات الفعلية (حقل `RESTE_PAYER` القديم غير محدَّث) ≈ 46,892 د.ل.
- المصاريف التاريخية على حساب مالي **أرشيفي غير نشط** بلا حركات → لا أثر على الخزائن الحالية؛ لا حركات مالية تاريخية.
- حركات الصنف: تُستورد كلها بمعرّفاتها؛ الجرد والمصادر الأخرى كـ`adjustment` مع `reference_table = legacy:<المصدر>`.
- المخزون (`pos_stock`): يُضاف فقط للأزواج (موقع، صنف) التي لا صف لها حالياً؛ الصفوف الحية لا تُلمس (يظهر تاريخها القديم ثم حركات المنظومة الجديدة).
- لا تعديل على العدّادات.
